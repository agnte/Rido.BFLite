# Streaming Response Support

Rido.BFLite now supports streaming responses, allowing you to send real-time updates to clients as content is being generated. This is particularly useful for AI-powered bots that generate content progressively, such as those using large language models.

## Overview

The streaming functionality is based on the [Microsoft Teams SDK StreamingResponse implementation](https://github.com/microsoft/teams-sdk/blob/release/v1/dotnet/packages/Microsoft.TeamsAI/Microsoft.TeamsAI/Application/StreamingResponse.cs) and has been adapted to work seamlessly with the BFLite architecture.

## Features

- **Progressive Updates**: Send partial message text as it's generated
- **Informative Updates**: Send typing indicators with status information
- **Citations**: Include references and sources in your streamed responses
- **Feedback Loop**: Enable thumbs up/down feedback in Microsoft Teams
- **AI Label**: Add "Generated by AI" label to responses
- **Attachments**: Include attachments in the final message

## Basic Usage

Here's a simple example of how to use streaming responses:

```csharp
using Rido.BFLite.Core;
using Rido.BFLite.Core.Schema;
using Rido.BFLite.Teams;

// In your message handler
botApp.OnMessage = async (activity, cancellationToken) =>
{
    // Create a streaming response
    var streamingResponse = new StreamingResponse(botApp, activity);
    
    // Send an informative update
    streamingResponse.QueueInformativeUpdate("Generating response...");
    
    // Stream chunks of text as they're generated
    streamingResponse.QueueTextChunk("Hello ");
    streamingResponse.QueueTextChunk("from ");
    streamingResponse.QueueTextChunk("streaming!");
    
    // End the stream and wait for all messages to be sent
    await streamingResponse.EndStream();
};
```

## Advanced Usage

### With Citations

```csharp
botApp.OnMessage = async (activity, cancellationToken) =>
{
    var streamingResponse = new StreamingResponse(botApp, activity);
    
    // Add citations
    var citations = new List<Citation>
    {
        new Citation
        {
            Title = "Source Document",
            Content = "This is the content from the source...",
            Url = "https://example.com/doc1"
        }
    };
    streamingResponse.SetCitations(citations);
    
    // Stream content with citation references
    streamingResponse.QueueTextChunk("According to [doc1], the answer is...");
    
    await streamingResponse.EndStream();
};
```

### With Feedback Loop and AI Label

```csharp
botApp.OnMessage = async (activity, cancellationToken) =>
{
    var streamingResponse = new StreamingResponse(botApp, activity)
    {
        EnableFeedbackLoop = true,
        FeedbackLoopType = "default",
        EnableGeneratedByAILabel = true
    };
    
    streamingResponse.QueueInformativeUpdate("Processing your request...");
    
    // Simulate AI content generation
    foreach (var chunk in GenerateAIContent())
    {
        streamingResponse.QueueTextChunk(chunk);
        await Task.Delay(100); // Simulate processing time
    }
    
    await streamingResponse.EndStream();
};
```

### With Attachments

```csharp
botApp.OnMessage = async (activity, cancellationToken) =>
{
    var streamingResponse = new StreamingResponse(botApp, activity);
    
    streamingResponse.QueueTextChunk("Here's your data analysis:");
    
    // Add an attachment to the final message
    streamingResponse.Attachments = new List<Attachment>
    {
        new Attachment
        {
            ContentType = "application/vnd.microsoft.card.adaptive",
            Content = new
            {
                type = "AdaptiveCard",
                body = new[]
                {
                    new { type = "TextBlock", text = "Analysis Results" }
                }
            }
        }
    };
    
    await streamingResponse.EndStream();
};
```

## Stream Types

The library defines three stream types as literal constants:

- `StreamType.Informative`: For informative updates (e.g., "Processing...")
- `StreamType.Streaming`: For partial message content chunks
- `StreamType.Final`: For the final complete message

## Exception Handling

The streaming response will throw a `StreamingException` if you try to queue updates after the stream has ended:

```csharp
try
{
    streamingResponse.QueueTextChunk("More text");
    await streamingResponse.EndStream();
    
    // This will throw StreamingException
    streamingResponse.QueueTextChunk("Too late!");
}
catch (StreamingException ex)
{
    Console.WriteLine($"Streaming error: {ex.Message}");
}
```

## Best Practices

1. **Always End the Stream**: Make sure to call `EndStream()` to send the final message
2. **Wait for Completion**: Use `await` on `EndStream()` to ensure all messages are sent
3. **Handle Exceptions**: Wrap streaming code in try-catch blocks to handle errors gracefully
4. **Reasonable Chunk Sizes**: Send meaningful chunks of text, not individual characters
5. **Use Informative Updates**: Keep users informed about long-running operations

## API Reference

### StreamingResponse Class

#### Constructor
```csharp
public StreamingResponse(BotApplication botApplication, Activity incomingActivity)
```

#### Properties
- `string Message`: The accumulated message text
- `List<Attachment>? Attachments`: Attachments to include in the final message
- `List<ClientCitation>? Citations`: Citations for the response
- `bool? EnableFeedbackLoop`: Enable thumbs up/down feedback (default: false)
- `string FeedbackLoopType`: Type of feedback loop (default: "default")
- `bool? EnableGeneratedByAILabel`: Show "Generated by AI" label (default: false)
- `string? StreamId`: The ID of the stream (assigned after first message)

#### Methods
- `void QueueInformativeUpdate(string text)`: Queue an informative update
- `void QueueTextChunk(string text, IList<Citation>? citations = null)`: Queue a text chunk
- `Task EndStream()`: End the stream and send the final message
- `void SetCitations(IList<Citation> citations)`: Set citations for the response
- `int UpdatesSent()`: Get the number of updates sent
- `Task WaitForQueue()`: Wait for the queue to be empty

## Migration from Microsoft Teams SDK

If you're migrating from the Microsoft Teams SDK, the main differences are:

1. **Constructor**: Takes `BotApplication` and `Activity` instead of `ITurnContext`
2. **Namespace**: Types are in `Rido.BFLite.Core` and `Rido.BFLite.Core.Schema`
3. **Literal Types**: Uses string constants instead of enums (e.g., `StreamType.Streaming` is a string constant)
4. **Exception Type**: Uses `StreamingException` instead of `TeamsAIException`

The API surface and usage patterns remain very similar to make migration straightforward.
